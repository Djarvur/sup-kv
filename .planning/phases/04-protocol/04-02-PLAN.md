<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gRPC client → handler | Untrusted local/LAN clients send keys and flags; the gate and key validation are the only admission controls. |
| listing mirror → handler | The adapter's atomic mirror is the sole source of "a peer knows this key"; a wrong answer overwrites a peer value (F14). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-06 | Tampering | `Get` listed-key answer | high | mitigate | Tombstone-visible `Engine.Version` probe distinguishes NotFound from Unavailable; the listed check never runs before the gate. |
| T-4-07 | Tampering | `Set` create_if_absent | high | mitigate | Listed key returns AlreadyExists before the engine call, closing the F14 overwrite path; race test covers the gate-open instant. |
| T-4-08 | Information disclosure | listed-key membership | low | accept | Membership is revealed through Unavailable vs NotFound; keys are already broadcast in listings to every segment host under the trusted-LAN model. |
| T-4-09 | Denial of Service | gated reads | low | accept | Reads are refused with a status, not held; the backstop opens the gate so a peerless node cannot stay unreadable forever. |
| T-4-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new dependency; the existing gRPC/protobuf pins are unchanged. |
</threat_model>
