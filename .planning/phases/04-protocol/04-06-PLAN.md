## Artifacts this phase produces

This plan adds: `persist.RestoredRecord`, `Engine.Restore(name) ([]RestoredRecord, error)`, `replayRecord` returning `(version.RecordVersion, replayed bool, error)` — the bool is an explicit replayed/skip signal, distinct from `RestoredRecord.Deleted` — the dump-failed notify branch in `Set`/`SetIfAbsent`/`Delete`, the snapshot-load notify loop, and the grpcapi harness `notify` capture.

<objective>
Make replication total: every local change reaches the wire, including a write whose dump failed and every record a snapshot load replays.

Purpose: S-02 names the hole — replication currently depends on the RPC's success path, so a failed-but-installed write and a whole snapshot load are invisible to peers. Both changes are small seam extensions: the engine already stamps the version before the flush, and the restore already replays fresh versions.
Output: the engine's replayed-record return, the two handler notify paths, and tests proving both reach the notify seam with the right flags.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| write handler → replication seam | The handler decides whether a write reaches peers; dropping it silently loses the only copy that exists beyond local memory. |
| snapshot load → replication seam | A load rewrites arbitrary many keys; each must replicate or peers diverge. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-18 | Repudiation | dump-failed write path | high | mitigate | Notify on `ErrDumpFailed` before returning Unavailable; the write enters the pending ledger and stays visible as unacked (PROTO-08). |
| T-4-19 | Tampering | snapshot-load notify | high | mitigate | Notify exactly the replayed records the engine returns, in sorted order; skipped records are never announced, so peers never receive a version that was not installed. |
| T-4-20 | Denial of Service | load notify burst | medium | mitigate | Replayed records ride the existing paced record-send queue; notify is enqueue-and-return, never a synchronous broadcast burst. |
| T-4-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new dependency. |
</threat_model>
