<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| peer Hello → listing queue | Any segment host controls node_id and run_id and can send Hellos at will; every accepted Hello can mint listing work. |
| source handle → queue identity | The datagram source is attacker-chosen; using it as a key is the CR-01 defect. |
| store → listing build | One build copies the whole key→version view; triggering it per datagram is a CPU/memory DoS. |

| T-4-23 | Denial of Service | restart/first-seen listing flood | high | mitigate | Destinations bounded (32), queued chunk work bounded (65 536), counted drops; destinations keyed by (node_id, run_id); old-run FIFOs dropped on restart (CR-01). |
