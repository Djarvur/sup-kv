<objective>
Add the version-only clock absorption seam, the O(1) key count and the content generation the rest of the phase depends on.

Purpose: PROTO-01 requires the HLC to absorb each listing part's maximum version so a post-listing local write beats the peer's state; PROTO-02 requires an O(1) empty-vs-data decision without cloning the store; PROTO-04's cached listing build needs a content generation so a build cannot outlive a store mutation. All three are one-method additions to existing seams — the store's clock, its record map and the engine's pass-throughs — and all three ripple to every `StateStore` implementer.
Output: the three store methods, their engine pass-throughs, the interface methods and per-part call, and a compiling, green module.
</objective>

## Scope rationale

The 14 declared files are the irreducible footprint of three interface methods: every `StateStore` implementer (engine, simulator store, pre-existing test fakes, plus 04-01's white-box fake) must satisfy `Observe` and `Generation` in the same commit or the module does not compile, and the store/engine tests pin the behaviors. That is one contract rippling through its implementers, not independent work. The estimate (45k tokens) is well under the smart-zone budget.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| peer listing → store clock | Attacker-influenced versions cross into the HLC; an unbounded advance would let one bad peer poison every future local write. |
| core → store | The core's single driver goroutine calls the store; a record-touching method here would corrupt state under replication. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-10 | Tampering | listing version → HLC | high | mitigate | Observe runs only after `versionAccepted` (MaxClockLead) and full header validation; discarded datagrams never reach the clock; `TestSync_observePerPartEmptyAndDiscarded` pins it. |
| T-4-11 | Denial of Service | startup key count | low | mitigate | `Len` is O(1) under RLock and clones no Data; the selection path never calls `Records()`. |
| T-4-43 | Tampering | cached listing build | high | mitigate | `Generation` moves only inside `install`, so a no-op or read path cannot mask a real mutation; the build caches the generation it was built at (04-08), and a mismatch forces a rebuild before the next listing. |
| T-4-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new dependency; only stdlib and existing internal packages. |
</threat_model>
