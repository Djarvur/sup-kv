<objective>
Make reactive replies identity-only and make a stale record answer with the newer one instead of a false Ack.

Purpose: CR-02 is a remotely triggerable retention defect — a listing reveals every key, and every stale-but-valid version can make this node queue a full value copy that the drain never uses. PROTO-03 is the honesty half: acknowledging a record you refused to apply tells the sender a lie. Both fixes live on the same queue/answer seam, so they land together.
Output: a key-only egress queue with drain-time construction, the strict-three-way replication outcome, and regression tests including the real-adapter `acked:false` proof.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| peer DataReplication → apply path | Any segment host can send a stale-but-valid record; the answer/ack decision is attacker-triggerable. |
| peer listing/request → egress queue | Broadcast listings reveal every key, so any host can fill the queue; retention is the DoS surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-15 | Denial of Service | egress queue retention | high | mitigate | Identity-only entries (key + struct) with a 32 768 cap; no Data copy before dedupe; drain-time lookup; retention bound test (CR-02). |
| T-4-16 | Repudiation | stale-record Ack | high | mitigate | Strictly older is answered with the newer record and never Acked; equal still Acks; the real-adapter wait reports `acked:false` (PROTO-03). |
| T-4-17 | Denial of Service | stale reply amplification | medium | mitigate | The reply goes through the single paced egress queue and its (handle, kind, key) dedupe, so a repeated stale flood collapses to one queued answer per key. |
| T-4-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new dependency. |
</threat_model>
