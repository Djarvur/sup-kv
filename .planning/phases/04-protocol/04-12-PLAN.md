Write `docs/04-MULTI-NODE.md` with these sections, each stating only what the code/tests establish:
1. Intro paragraph naming ADR 0009 and the sibling docs (`OPERATIONS.md`, `EXAMPLES.md`), in the OPERATIONS style.
2. `## Traffic shape` — one broadcast listing per `sync_interval` reaching every peer, one datagram per chunk; each first-seen or restarting peer additionally receives one unicast targeted listing; a joining node therefore receives up to N−1 targeted plus N−1 periodic listings; a sender's listing work is one chunk stream, not N copies; reactive replies share one egress queue at `sync_response_rate`.
3. `## Timing` — normal write visibility is one write broadcast (one RTT); a partition heal without eviction converges within the existing `2 × sync_interval + response` bound; a heal after eviction converges at the next Hello plus `N / sync_response_rate` (first-seen listing, no `sync_interval` term); a joining node converges at its first Hello listing.
4. `## wait_for_replication at N > 2` — `total` is the peer count captured at write time; `acked=true` needs every one of those peers to Ack, so one unreachable peer yields false at timeout; an Ack from a peer unknown at write time counts in the core set but is clamped to `total`; record IN-05 (a peer discovered after the write-time snapshot joins the wait set but not `total`, so a fully covered write can report false — the safe direction) and name Phase 6 APIS-01 as the owner of any tightening and of the final `docs/API.md` wording.
5. `## Protocol bounds` — the actual constants with the rationale: sync streams 16, entries per stream 65 536, total entries 131 072, chunk count cap 65 536, listing destinations 32, queued listing chunks 65 536, seen-run ring 8; name the counters (`SyncStreamDropped`, `ListingDropped`, `NotificationsRegressed`) and that drops are counted, never silent.
6. `## Three-node topology in tests` — the in-process three-adapter shared-port test as the real-socket proof; unicast to a reuse-address port is kernel-arbitrary, so broadcast convergence is asserted there and unicast semantics are covered by the simulator and the two-port integration harness; the production binary intentionally has no reuse flag.
7. `## Residual windows (accepted)` — (a) a mixed cluster where the gate opens on an empty peer's complete listing before a data peer's listing arrives (D-01's literal reading, kept; first-Hello listings shrink it to the hello cadence); (b) a read of a listed-but-not-yet-arrived key returns Unavailable while Delete keeps the local NotFound (14.5(6) covers reads only); (c) the peer table itself is unbounded (pre-existing trusted-LAN risk, Phase 7 hardening); (d) listing drift does not feed MergeStats (Phase 7 OBSV-05).
8. `## Handoffs` — Phase 6 (APIS-01/DOCS-05) owns `docs/API.md` wording; Phase 9 owns the node-replacement runbook text including the `startup_gate_empty` 60 s wait; Phase 7 owns the one-point config-relation validation and the drift catalog.
