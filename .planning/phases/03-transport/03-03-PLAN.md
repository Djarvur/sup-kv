In `internal/app/version/version.go` add:

1. Sentinels: `ErrVersionLayout` ("the 16 bytes are not an RFC 9562 UUIDv7") and `ErrVersionFuture` ("the reading is beyond now + max_clock_lead"), declared with `errors.New` and wrapped/returnable directly.
2. `func (v RecordVersion) Validate(now time.Time, maxLead time.Duration) error`: first check the layout (`v[6]&0xF0 == uuidVerBits` and `v[8]&0xC0 == uuidVarBits`) returning `ErrVersionLayout`; then unpack `l` with `Unpack`, compute `nowMs := now.UnixMilli()` and `lead := maxLead.Milliseconds()` (negative -> 0), and return `ErrVersionFuture` only when `l >= nowMs && l-nowMs > lead` — the subtraction form avoids overflow for a 48-bit `l` and an absurd lead. A `l` in the past is always accepted (the HLC absorbs it). Add a doc comment naming XPORT-04, the 60 s default rationale (equals the documented drift tolerance so peers inside it stay accepted), and the filler-bit decision.

Create `internal/app/version/validate_test.go` (package version_test, matching version_test.go's clause if external). Table tests:
- valid version packed at now passes; packed at now-24h passes.
- exactly `now + maxLead` passes; `now + maxLead + 1ms` returns ErrVersionFuture (errors.Is).
- `ff...ff` rejected (layout and/or future) at any lead.
- wrong version nibble (0x60) and wrong variant (0x00/0xC0) return ErrVersionLayout.
- negative maxLead behaves as zero (only `l <= nowMs` accepted).
- an accepted version with random filler bits set in octets 11-15 and the low 6 bits of octet 10.
- fractional `now` (nowMs + 900µs) accepts `l == nowMs + leadMs` and rejects +1 ms.
- absurd maxLead (`math.MaxInt64/2` nanoseconds) does not overflow: a past `l` passes, `ff...ff` still fails layout.
