<objective>
Make the write half of `wait_for_replication` honest end-to-end: capture the peer-id set immediately before the engine write, carry it through the notification into the core's pending entry and the adapter's tracker, answer zero peers and a nil seam with `(false, 0, 0)` immediately, and publish one atomic peer-id mirror for the production wiring.

Purpose: A-01 — the current report is an overstatement (zero peers says acked) and a moving target (peers discovered mid-wait join the wait-set but not the total, producing a false negative at the timeout). This plan is the tracer slice: the captured peer slice crosses handler → adapter → core → report. The tracker promise-set enforcement, discovery-flush split and the full regression matrix follow in the expansion plan 06-11.
Output: `ServerOptions.WritePeers`, peer-carrying `LocalNotify`, `Core.PeerIDs`/`PeerGeneration`, an adapter `KnownPeerIDs` mirror, captured-peer seeding of the core wait-set, and every call site (including `Cluster.NotifyInstalled` and `Server.notifyReplayedWrite`) traced to the new shape.
</objective>

<assumptions>
Probe rows owned by this plan (specless fallback, unresolved):

- **APIS-01 (concurrency) — what is guaranteed under parallel writes?** Assumption: the handler captures the peer set in one read before the engine call; concurrent writes each capture their own set; a newer write under the same key supersedes the older tracked version and resolves it through `ResultSuperseded`. Resolution: the tracker is per `(key, version)`, `trackLocalWrite` keeps the supersession guards unchanged, and the tracker map is bounded by concurrent waits because every wait path deletes.
- **APIS-01 (boundary) — zero/one peer and one step either side.** Assumption: zero captured peers → `(false,0,0)` and a release call; one captured peer → wait for its Ack; a captured peer that has already left the core peer table → `WaitSetEmpty` (honest false) instead of a timeout; a peer discovered one instant after capture → broadcast but not awaited. Resolution: all four are tests in this plan.
- **Decision fidelity:** D-01 chose the write-time peer set + immediate zero-peer answer + Superseded fast path. No deferred idea is implemented.
- **Scope rationale (19-file signature ripple):** the file count is the mechanical ripple of one atomic signature change — the production seam, the adapter, the core, the simulator, the binary wiring, and every test call site that must keep compiling. Moving the test-call-site updates to a later plan would leave `go vet ./...` red between plans; the behavioral additions and the regression matrix are split into plan 06-11 instead.
</assumptions>
