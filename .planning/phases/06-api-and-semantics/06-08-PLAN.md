<objective>
Implement 14.1: a snapshot load is a full rollback. Keys absent from the snapshot are deleted with fresh tombstones, the replay and rollback run as one deterministic sorted union, the returned list includes the rollback tombstones so the existing SnapshotLoad notify path broadcasts them, and the additive-pinning tests are rewritten.

Purpose: S-01/APIS-07 — `Restore` currently touches only the snapshot's keys, so post-snapshot keys survive a load while the test's own doc comment claims rollback. The result must also replicate (PROTO-08 already broadcasts exactly the returned list).
Output: the rewritten `restoreChanges`/`replaySnapshot`, updated docs, the rewritten `TestEngine_snapshotCreateLoadRestore` and `TestEngine_restoreReturnsReplayed`, the extra-live-key no-op test, and the RPC rollback/broadcast test.
</objective>

Probe rows owned by this plan (specless fallback, unresolved):

- **APIS-07 (unclassified) — the rollback contract.** Assumption: "full rollback" means the snapshot is the state: snapshot keys replay as fresh-version writes/deletes; current live keys absent from the snapshot are deleted with fresh tombstones; current tombstones absent from the snapshot are already deleted and stay untouched; concurrent writes after the rollback set is computed are ordinary LWW, not snapshot isolation. Resolution: the three tests and the doc-comment rewrite.
- **Boundary — an empty snapshot vs an empty store.** Assumption: a snapshot with no records against a store with live keys deletes every live key (a rollback to empty); an empty store loading an empty snapshot is a no-op. Resolution: the extra-live-key no-op test and the existing no-op test.
- **Decision fidelity:** D-07 chose full rollback with broadcast and the test rewrite. No deferred idea is implemented.
</assumptions>
