<objective>
Pin the gRPC transport envelope and make health one-way: a testable `TransportLimits` struct derived from the effective value limit and the List page budget, explicit keepalive/enforcement parameters, a production `grpc.NewServer(limits.ServerOptions()...)`, and a `Server.Shutdown()` that calls the standard health server's `Shutdown` before the API context is cancelled.

Purpose: A-05 — the server currently relies on gRPC defaults (4 MiB recv, 2 h keepalive) and shutdown flips health to NOT_SERVING, then `apiCancel` can let the gate resolver flip it back to SERVING. The standard health server's one-way `Shutdown` closes that race.
Output: `internal/grpcapi/limits.go`, the limits tests, the one-way health test, and the binary wiring.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → gRPC transport | Request size, ping cadence, and stream lifetime are untrusted. |
| Server → health endpoint | Orchestrators gate traffic on the health status during shutdown. |
| Config → transport limits | The effective value limit determines the legitimate maximum request. |
