<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Store install → Watch hub | The tap runs under the store write lock and must never block. |
| Startup dump → hub | A loaded dump is not a change feed, and a nil tap is a valid caller contract. |
| Client → Watch stream | Prefix, subscriber lifetime, and slow-reader behavior are untrusted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-18 | Denial of Service | `WatchHub.pending` | high | mitigate | Pending is bounded by `watchIngress`; overflow disconnects all subscribers and clears pending; resubscribe plus snapshot heals. |
| T-06-19 | Spoofing | `shutdownSubscribers` | high | mitigate | Every shutdown close writes a fresh `codes.Unavailable` status; the handler returns it, so a dying node never looks like a clean end of stream. |
| T-06-20 | Denial of Service | `persist.Open` startup tap | medium | mitigate | A synchronous, nil-safe loading guard suppresses the tap around `mergeRecords`; a loaded dump cannot fill the hub queue and a nil callback cannot panic. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed by this plan; any dependency added later requires the package-legitimacy gate and a blocking human checkpoint. |
</threat_model>
