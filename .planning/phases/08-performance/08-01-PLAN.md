<objective>
Stand up the phase's operator-facing measurement pipeline end-to-end on the one row that already has a proven scenario: the 1000 writes/s distinct-key burst. This plan creates the single threshold table, the perf/race gates, the hardware block and the dump-directory guard in `internal/testutil`, adds `internal/stand/perf_test.go` with the burst row, and adds `make perf` as the one named target — then proves the whole path by running it.

Purpose: D-06 needs one command, one threshold place and a hardware description per number, and D-02 needs the XPORT-02(3) burst to be a standing bound rather than folklore. Doing it on the burst first proves the measurement→threshold→target architecture on a scenario that is already green (`TestPerfBurstDistinctKeys` is the operator-facing twin of `TestRed_R02_burst`), so the later stand rows (latency, amplification, memory) only add measurement code to a proven pipeline.
Output: `internal/testutil/perf.go` (+ the Linux/non-Linux and race build-tag pair), `internal/stand/perf_test.go` with `TestPerfBurstDistinctKeys` and the frozen-contract drift guard, and a `perf` target in `Makefile`.
</objective>
