<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| store write lock → hub goroutine | Events cross via a bounded non-blocking ingress; blocking here would stall every write on the node |
| hub goroutine → subscriber streams | Per-subscriber bounded channels; a stalled reader must not consume unbounded memory or stall others |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | DoS | OnChange tap under the store write lock | high | mitigate | Fan-out is a select-with-default into a bounded ingress — the store never waits on any subscriber; slow consumers are disconnected (ResourceExhausted), never silently served holes (D-02 preserved by re-snapshot on resubscribe); TestWatch_slowConsumer locks store liveness |
| T-05-06 | DoS | WatchHub subscriber table (subscription flood) | medium | accept | v1 trusted-LAN trust model: no per-node subscriber cap in v1; each subscriber costs one bounded channel (watchBuffer events max), so memory is bounded per subscriber; documented as an operational envelope, revisit with OBS work in Phase 6 |
| T-05-SC | Tampering | package installs | high | mitigate | No package installs in this plan; the phase dependency set is pinned and proxy/sumdb-verified in 05-01 — go.mod/go.sum untouched here |
