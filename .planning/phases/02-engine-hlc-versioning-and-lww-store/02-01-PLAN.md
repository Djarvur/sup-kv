  <action>
  Expand the store to the full CORE semantics. The visibility rules are deliberately asymmetric (Pitfall 1) — encode exactly this table: Get: no record or record.Deleted → ErrNotFound; Set: unconditional replace; SetIfAbsent: record present (regardless of Deleted) → ErrAlreadyExists; Delete: no record or already Deleted → ErrNotFound, else write a tombstone (planner decision on research Open Question 1: no version is burned on a no-op).

  SetIfAbsent(key string, data []byte) (RecordVersion, time.Duration, error): size check first (ErrValueTooLarge), then under the write lock — if any record exists for the key, return ErrAlreadyExists; otherwise the same Tick/pack/store path as Set.

  Delete(key string) (RecordVersion, time.Duration, error): under the write lock — if no record or the record is already a tombstone, return ErrNotFound; otherwise Tick, store Record{Version: fresh, Data: nil, Deleted: true, Checksum: RecordChecksum(key, fresh, nil, true)}, keep the tombstone in the map forever (never drop tombstoned keys — an older Set must not be able to resurrect a deleted key).

  Merge(key string, rec Record) (conflicts []Conflict, drift time.Duration, err error): validate len(rec.Data) against ValueMaxBytes first — oversized remote data returns ErrValueTooLarge and nothing is stored (the record never enters the map); copy rec.Data defensively (Pitfall 4). Compare rec.Version against the stored version with the full 16-byte Compare — comparing only (l, c) is forbidden (VERS-01: the NodeID tie-break is what makes the winner identical on every replica). Strictly greater incoming replaces the stored record and returns conflicts = one Conflict{Key: key, Winner: incoming, Loser: stored}; strictly lesser keeps the stored record and returns Conflict{Key: key, Winner: stored, Loser: incoming} — the rejected older record is also a displaced version (CORE-07); equal version is a full no-op returning nil conflicts (Pitfall 3 — duplicate delivery must not create journal noise). After the comparison, advance the clock by calling Update with the unpacked rec.Version fields and return the observed drift. The remote record keeps ITS OWN version — never re-stamp it with a fresh local Tick (that would destroy the CRDT laws). Tombstoned records participate in merge comparison exactly like live ones.

  Add method Records() map[string]Record returning a full snapshot of the map — tombstones included, Data defensively copied — under the read lock. This is the Phase 3 dump source (PERS-01 serializes exactly this map) and the state-comparison primitive the plan 02-03 merge-law property tests diff; Get alone cannot see tombstones by design.
