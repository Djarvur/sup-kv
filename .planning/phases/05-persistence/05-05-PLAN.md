Consolidated list for the whole phase (later plans add to it in their own sections). This plan creates:
`port.FailureClass`, `port.ClassedError`, `port.FailureClassOf`; `persistfile.corruptSuffix`, `prevSuffix` reuse, `defaultOrphanTempAge`, `preserve`, `sweepOrphans`, `ensureDir`, `tolerateDirSyncErr`, `classifySaveError`; and the load-outcome/sweep/save-error test files.

<objective>
Make dump-load outcomes explicit and evidence-preserving, and finish P-09's file hygiene — PERSIST-02 and PERSIST-09.

Purpose: today `Load` returns `(bytes, ok)` and swallows every read and parse error, so "no files" and "both corrupt" are indistinguishable; worse, a backup start leaves the corrupt main in the rotation path, and the first save rotates it over the good `.prev`. Preservation at load is what keeps `.prev` alive, so the outcome model and the rename are one design. The same plan completes the remaining P-09 work: an age-bounded orphan sweep, a parent-directory sync when a new directory is created, and a directory-fsync tolerance that never masks a file-data error.
Output: the outcome/failure result, preservation with collision suffixes, the rotation-survival proof, the sweep, the parent sync, the directory tolerance, and the errno-to-`FailureClass` classification.
</objective>

## Scope rationale

Ten files across one adapter contract: the load outcome, evidence preservation, the orphan
sweep, the parent sync and the errno classification are one `Load`/save lifecycle. Preservation
must happen at load before any save (otherwise the first rotation destroys `.prev`), so it
cannot be split from the outcome model; the sweep and parent sync are the same file-hygiene
deliverable as PERSIST-09. The test files are the tables for those three behaviors.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dump directory → loader | Any local actor can write, truncate, chmod or replace a generation file. |
| loader → evidence rename | A hostile path or symlink must not redirect or destroy preserved evidence. |
| save → directory entries | A newly created directory's entry is not durable until its parent is synced. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-5-12 | Tampering | rotation destroying the last good generation | high | mitigate | Unusable generations are renamed out of `main`/`.prev` at load; the rotation-survival test compares `.prev` bytes across the first save. |
| T-5-13 | Tampering | symlink or non-regular file at the dump path | medium | mitigate | `Lstat` decides regularity; only regular files are renamed; `Rename` replaces the link itself; the directory is 0700. |
| T-5-14 | Tampering | sweep deleting a live file | high | mitigate | Exact `dump-` prefix, regular files only, one-hour age bound, `.prev`/`.corrupt-*`/main excluded; the table seeds every exclusion. |
| T-5-15 | Repudiation | fsync error silently treated as success | high | mitigate | Only the directory step tolerates ENOTSUP/EINVAL; file-data sync keeps every error and its failure row still fails the save. |
| T-5-16 | Information Disclosure | errno text leaking through the core | low | mitigate | `syscall` stays in the adapter; the core consumes only `port.FailureClass`. |
| T-5-SC | Tampering | npm/pip/cargo installs | high | mitigate | No dependency is added. |
</threat_model>
