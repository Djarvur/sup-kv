## Artifacts this phase produces

Consolidated list for the whole phase (later plans add to it in their own sections). This plan creates:
`storage.ValueMaxBytes` (the only production definition of 61440), `storage.Config.ValueLimit()`, `storage.Store.ValueMaxBytes()`, `persist.Engine.valueMaxBytes`, the limit parameters on `persist.Encode`/`persist.Decode`, `cmd/sup-kv`'s `errValueMaxBytesRange` and `checkValueMaxBytes`, and removes `storage.defaultValueMaxBytes`, `persist.maxRecordBytes` and `cmd/sup-kv`'s `defaultValueMaxBytes`.

<objective>
Make the value limit one runtime value owned by the store and read by the codec (D-01), closing P-01's silent data loss end to end.

Purpose: the store accepts a value up to `Config.ValueMaxBytes`, the encoder writes it, `Set` confirms it, and today the decoder's frozen 61 440 then discards it on the next start. The decoder runs before the store exists (its clock is seeded from the decoded records), so the design is one exported constant plus a `Config.ValueLimit()` helper the decode can call before `NewStore`, and a `Store.ValueMaxBytes()` accessor the encoder captures after. `persist.Open` keeps its frozen `(*Engine, int)` signature: the rich load report is a later plan's `LoadStats()`.
Output: the single constant and both helpers, the codec's configured limit, the engine wiring, the binary's validation and constant removal, the mechanical call-site sweep, and the three new pins plus the frozen process-level acceptance.
</objective>

## Scope rationale

Thirteen files is the atomic width of the single-source change, not three concerns: deleting
`maxRecordBytes` changes the `Encode`/`Decode` signatures, so every call site in five packages
must move in the same commit or the tree does not compile (the "keep each plan's task
compile-green" rule). The non-`store.go`/`codec.go`/`engine.go`/`main.go` files are mechanical
limit arguments at existing fixtures — no new behavior, no new test design.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator config → process | `--value-max-bytes`/`SUPKV_VALUE_MAX_BYTES` decides how much payload the node accepts; an invalid value could silently mean "the default" instead of an error. |
| dump file → decoder | The decoder's size bound is the data-loss site: a bound lower than the configured store limit discards confirmed writes at the next start. |
| store → encoder | The encoder must never silently drop a record the store accepted; a disagreement is data loss. |

| T-5-SC | Tampering | npm/pip/cargo installs | high | mitigate | No dependency is added: the phase is Go stdlib and in-repo packages only; no package-install task exists in this plan. |
