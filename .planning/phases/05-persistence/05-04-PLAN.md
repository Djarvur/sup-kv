## Artifacts this phase produces

Consolidated list for the whole phase (later plans add to it in their own sections). This plan creates:
`port.LoadOutcome` (`LoadPrompt`, `LoadMain`, `LoadBackup`, `LoadUnusable`), `port.Generation` (`GenMain`, `GenPrev`), `port.GenerationFailure`, `port.LoadResult`, `port.DumpStore.SaveStream` and the new `Load(now, parse)` shape; `persist.EncodeTo`; `FileStore.SaveStream`; `fsops.write(dir, fill)`; the adapter's `maxDumpBufioBytes` constant; and the `BenchmarkDumpCycle` peak sample.

<objective>
Make a dump cycle stream and give the port the load-outcome contract the rest of the phase consumes — PERSIST-06, with PERSIST-11's port half.

Purpose: today `runDump` holds `Records()`'s deep copy plus `Encode`'s `bytes.Buffer` plus `Save`'s whole byte slice, so peak live heap is several state sizes and the writer pause is measured at 74 ms. `SaveStream(fill)` lets the adapter supply the temp writer and the engine fill it with `EncodeTo`, cutting peak live to one state copy plus one line. The same port revision adds `LoadResult`, which the adapter, the engine report and the totality seam all consume; changing the interface forces all four implementations in one task (the ripple pitfall).
Output: the port v2 contract, `EncodeTo` and streaming `runDump`, the adapter's fill-based save with its hygiene, the three test doubles, and the structural and measured proofs.
</objective>

## Scope rationale

Thirteen files, driven by one interface change: adding `SaveStream` to `port.DumpStore` and
`Load`'s result shape forces every implementation (the real adapter plus three test doubles) and
every call site into the same commit or nothing compiles. The port's load result is included
here rather than split out because the same interface edit must be atomic; the remaining file
entries are the mechanical width of that edit plus the two structural test files. This is the
"port ripple" exception the estimate budget accepts.
