## Artifacts this phase produces

Consolidated list for the whole phase (later plans add to it in their own sections). This plan creates:
`persist.LoadStats` with `Loaded`, `Outcome`, `Generation`, `Failures`, `Decoded`, `Swept`, `SweepErr`; `Engine.LoadStats()`; the dirty-on-outcome rule and `markDirty`'s nudge; `metrics.Sources.LoadStats`; the `supkv_dump_load_total` and `supkv_dump_records_discarded_total` families; and `internal/stand/persist_test.go`.

<objective>
Surface every load outcome in the engine, the binary log and the metrics — PERSIST-02's visibility half — make the post-backup/empty start dirty with the nudge fix (PERSIST-04), and account for value-limit skips (PERSIST-10).

Purpose: the adapter now classifies and preserves, but the engine discards the report, the binary prints one count, and a backup start is clean — so `Snapshot` can copy the corrupt main and the first rotation can displace `.prev`. Mapping `LoadResult` into `LoadStats`, marking dirty on every non-Main outcome, moving the `changed` nudge into `markDirty`, and logging one line per class closes the visibility and lifecycle halves together. Skips become a named class with a count, a WARN and a metric, and the file keeps the evidence until normal rotation allows it.
Output: the report and accessor, the dirty/nudge rules, the skip accounting, the binary's one-line-per-class logs, the two metric families, and the process-level proofs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| load result → operator log | A data-losing start must be distinguishable from a first start in one line. |
