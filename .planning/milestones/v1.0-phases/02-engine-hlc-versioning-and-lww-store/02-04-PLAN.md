<objective>
Close gap G-02-VERS04-DOMINANCE (review finding WR-01): extend the restart seam so a restart seeds the clock from the dump's FULL watermark — the maximum l AND the maximum counter at that l — making every post-restart version strictly dominate every version in the dump, including watermark-millisecond versions with counter >= 1 and the store's own NodeID. This kills both demonstrated failure modes: an acknowledged post-restart write silently reverting on peer merge (probe variant A) and an equal-version collision silently dropping fresh data (probe variant B).

Mechanism choice (WR-01 offered two; this plan picks ONE): the initialC parameter, not the dumpMax+1 baseline. Rationale: WR-01's root criticism is that the seam carries insufficient information to preserve the package's own laws, and 02-VERIFICATION.md records that Phase 3 wires InitialL directly onto this seam — so the seam itself must express an exact restart. A dumpMax+1 convention stays unenforceable at the NewClock level (the exact deficiency class flagged) and discards the counter entirely; initialC makes the constructor state equal the dump watermark with zero algorithm change.

Purpose: Phase 3 (persistence) calls NewStore with dump-derived seeds; without this fix every restart that had 2+ writes (own or merged) in the dump's final millisecond can silently revert or split a key.
Output: extended NewClock and Config seams, the WR-01 dominance proofs in the unit, property and store-level suites.
</objective>
